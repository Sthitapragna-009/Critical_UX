# Jurisdiction files

Rules that only apply in one market live here, so the rest of the suite stays global without pretending UK or US norms are universal.

| File | Covers | Depth |
|---|---|---|
| `uk.md` | United Kingdom | Strong |
| `eu.md` | European Union / EEA | Strong |
| `us.md` | United States | Strong for credit, disputes, deposits; partial for dark patterns |
| `india.md` | India | Strong for consent, dark patterns, lending; partial for UPI screens |
| `brazil.md` | Brazil | Partial (secondary sources) |
| `singapore-sea.md` | Singapore and Southeast Asia | Strong for Singapore; QR standards not researched |
| `australia.md` | Australia | Partial |
| `other-regions.md` | China, Gulf, Africa and gaps | Thin; mostly gaps |

**How to use:** apply every file for the markets involved (user location, provider licence, destination). When markets conflict, design to the stricter rule. When a market is not covered, say so in your output and apply the strictest researched rule as a default.

**Dates:** every dated rule shows the date it applies from. Check the linked primary source before shipping; regulation changes often.

**Not legal advice.** These summaries are design guidance; compliance teams decide.
